# S4.3R 자동매매 구현 명세서 (Single Source of Truth) v1.1 (P0 원본 대조 완료)

> 이 문서만으로 S4.3R 전략을 다른 언어(Python)로 재구현하고, 키움 REST API 기반 자동매매를 만들 수 있어야 한다.
> 워크벤치(static/app.js, SHA-256 `ade2280a11378e90a9fa7fb15a8ba7947d9259029df91009492d2ae82ddad368`)의 S4.3 결과가 정답이다.
> 문서와 원본 코드가 다르면 원본 코드를 따르고, 이 문서를 고친다.

## 0. 구현 상태와 원본 대조 (2026-10-01)

- P0 구현: `s43r_engine.py`의 `S43REngine.step()` 하나를 스트리밍과 `evaluate()` 재생이 공유한다. 주문·계좌 API는 호출하지 않는다.
- 원본 SHA-256을 고정한 `scripts/s43r_oracle.cjs`와 `tests/test_s43r_engine.py`로 대조한다. JS 원본 파일은 변경하지 않는다. 조기 OFF/0.30은 원본 S4.3의 조기가속 조건만 메모리에서 바꾼다.
- 학습 자료는 명시된 20일, 572종목이다. 0.20/0.30 × ON/OFF 2,288개 결과의 진입 여부·시각·청산 사유·손익 소수 4자리와 부분익절 이벤트까지 일치했다.
- API 명칭·주문 방식·시장 데이터의 공급자 간 일치 여부는 P1/P2에서 별도 검증할 초안이다. 이 문서의 P0 완료는 시세 수집·모의/실계좌 운용 완료를 뜻하지 않는다.
- 각 이벤트의 `fraction`은 최초 포지션 대비 비중이다. 실전 수량 배분·미체결 처리는 별도 주문관리기에서 구현해야 한다.

## 2. 입력 데이터 규격

### 2.1 봉(Candle)
```
{ date: "YYYYMMDD", time: "HHMM", open, high, low, close, volume, amount? }
```
- 오래된 순서로 정렬한다. 전일 봉(시드)과 당일 봉이 하나의 배열에 들어 있다.
- `amount`가 없으면 `close × volume`을 쓴다.
- 시드 범위(전일 봉 개수와 시작점)는 지표값에 영향을 준다. 실전에서도 워크벤치 감사파일과 **같은 범위**를 써야 한다. (§11-4)

### 2.2 타임스탬프 생성 (buildStrictTimestamps)
- `date + time`을 워크벤치 실행 환경의 로컬 시각 epoch 초 (P0 기본값은 한국 UTC+09:00, 비교 Node도 `TZ=Asia/Seoul`)로 바꾼다. 앞 봉 이하가 되면 `앞 봉 + 1초`로 강제한다. 같은 분에 여러 360틱 봉이 생기는 경우를 처리하기 위한 규칙이다.
- `entry 이후 봉`인지는 이 타임스탬프로 판단한다.

## 3. 지표 (원본 수식 그대로, 시리즈 전체에 대해 계산)

### 3.1 VWAP
```
tp = (high + low + close) / 3
cumPV += tp × volume ; cumV += volume
vwap[i] = cumV > 0 ? cumPV / cumV : close
```
- **시리즈 전체 누적**이다. 당일 리셋이 없고 전일 시드부터 누적한다.

### 3.2 당일 누적대금 (억원)
```
당일 봉: run += (amount || close×volume)
당일이 아닌 봉: run = 0
cum[i] = run / 1e8
```

### 3.3 JMA(length=7, phase=0, power=2)
```
phaseParam = phase/100 + 1.5            // = 1.5
beta  = 0.45(L-1) / (0.45(L-1) + 2)     // L=7
alpha = beta^power
초기: e0 = close[0], e1 = 0, e2 = 0, jma = close[0]
i ≥ 1:
  e0 = (1-alpha)·src + alpha·e0
  e1 = (src - e0)(1-beta) + beta·e1
  e2 = (e0 + phaseParam·e1 - jma)(1-alpha)² + alpha²·e2
  jma = jma + e2
```

### 3.4 Supertrend(period=14, mult=2.0)
```
tr[0] = high-low ; tr[i] = max(h-l, |h-prevC|, |l-prevC|)
atr[13] = (tr[0..13] 합) / 14
atr[i≥14] = (atr[i-1]·13 + tr[i]) / 14
atr[0..12] = tr[i]                       // 초기 13개는 TR 그대로
hl2 = (h+l)/2 ; basicUp = hl2 - 2·atr ; basicDn = hl2 + 2·atr
up[0]=hl2_0-2atr0, dn[0]=hl2_0+2atr0, trend[0]=+1
up[i] = trend[i-1]==+1 ? max(basicUp, up[i-1]) : basicUp
dn[i] = trend[i-1]==-1 ? min(basicDn, dn[i-1]) : basicDn
trend[i] = trend[i-1]
  if trend==+1 and close < up[i] → -1
  elif trend==-1 and close > dn[i] → +1
```
- 런너 트레일에 쓰는 ATR도 이 `atr[i]`다. 값이 0이거나 없으면 `high-low`를 쓴다.

### 3.5 Normalized MACD Histogram(5, 13, 4)
```
i=0: emaF = emaS = close, sig = macd(=0)
i≥1: emaF += 2/6·(c-emaF) ; emaS += 2/14·(c-emaS)
     macd = emaF - emaS ; sig += 2/5·(macd-sig)
hist% = close>0 ? (macd - sig)/close × 100 : 0
```

### 3.6 파생 신호
```
jmaUp       = jma[i] > jma[i-1]
jmaTurnDown = jma[i] < jma[i-1]  AND  jma[i-1] ≥ jma[i-2]    (i<2이면 jma[i-2]=jma[i-1])
```

## 5. 종목별 판정 알고리즘 (의사코드)

```
function evaluateS43R(candles, cfg, officialMfe=None):
  if candles 비었음: return 데이터없음
  if cfg.apply_mfe_gate and officialMfe is not None and officialMfe < cfg.base_rate_pct:
      return MFE미달                                   # §6 참고

  지표 계산 (§3)
  capture = 0 ; startIdx = -1
  for i, c in candles where c.date == target_date:
      if c.time <= capture_time: capture = c.close        # 09:03 이하 마지막 봉 종가
      if c.time >= entry_start and startIdx == -1: startIdx = i
  if capture <= 0 and startIdx != -1: capture = candles[startIdx].open
  if capture <= 0 or startIdx == -1: return 09:04봉없음
  basePrice = capture × (1 + α/100)

  pos = None
  for i from startIdx:
      bar = candles[i]
      inWindow = bar.date==target_date and entry_start ≤ bar.time ≤ entry_cutoff

      # ---- 진입 ----
      if pos is None and not entered and inWindow:
          setup  = trend[i]==+1 and macd[i] ≥ macd_threshold and jmaUp
          normal = apply_mfe_gate ? (setup and close ≥ basePrice and ((close-capture)/capture)·100 ≥ α) : setup
          early  = early_enabled and setup and bar.time ≤ early_until
                   and cum[i] ≥ early_cum_eok and macd[i] ≥ early_macd
          ok = (normal or early)
          if ok and apply_cum_gate and cum[i] < min_cum_eok: ok = False
          if ok: 진입(entry=close, entryTs=bar.ts, runnerHigh=bar.high)

      # ---- 보유 관리: 진입봉 다음 봉부터 ----
      if pos and bar.ts > entryTs:
          pnl = (close/entry - 1)·100
          [1] runnerHigh = max(runnerHigh, high)
          [2] pnl ≤ hard_stop_pct          → 잔량청산 "초기손절(스탑{현재값:.1f}%)"
          [3] stg1 and pnl ≤ bep_pct        → 전량청산 "본전보호(BEP컷)"
          [4] !stg1 and pnl ≥ tp1 and jmaTurnDown → stg1=True, p1=close (30%)
          [5] stg1 and !stg2 and pnl ≥ tp2 and jmaTurnDown → stg2=True, p2=close (30%)
              ※ [4][5]는 같은 봉에서 연속으로 성립할 수 있다
          [6] stg2 and close < runnerHigh - atr_trail_mult·atr[i] → 잔량 "ATR동적트레일링컷"
          [7] trend[i]==-1 or (stg1 and close < vwap[i]·vwap_runner_cut)
                → 잔량 (stg1 ? "추세이탈(런너청산)" : "ST하락(손절)")
          [8] bar.date==target_date and bar.time > exit_soft:
                strong = trend[i]==+1 and close ≥ vwap[i]·vwap_extend
                if !strong or bar.time ≥ exit_hard → 잔량 ("추세연장마감(10:30)" / "10:03시간종료")
          청산되면 루프 종료 (재진입 없음)
```

### 5.1 손익 계산 (원 투입금 대비 %)
```
part = 0 ; rem = 1.0
if stg1: part += ((p1-entry)/entry)·30 ; rem -= 0.30
if stg2: part += ((p2-entry)/entry)·30 ; rem -= 0.30
pnl = part + ((exit-entry)/entry)·(rem·100)
```

### 5.2 체결 가정 (백테스트)
- 진입, 부분익절, 청산 모두 **해당 봉 종가**로 체결한다.
- 손절은 **종가 판정**이다. 봉 안의 저가로 판정하지 않는다. (봉 안 판정은 S4.4에서 기존 승자를 손실로 바꿔 기각됨)
- 원본 엔진 `pnl`에는 비용과 슬리피지가 없다. 튜너·본 문서의 기준 성적은 **청산 거래당 0.25%p를 별도 차감**한다. 엔진 결과와 비용 차감 성적을 혼용하지 않는다.
- 데이터가 끝나도 보유 중이면 `entered=true`, `exitReason="미체결"`, `pnl=0`이다. 부분익절이 있어도 반환 손익은 0이며 해당 이벤트는 유지한다. 강제 10:30 청산은 10:30 이후 봉이 실제 공급된 경우에만 일어난다.
- 진입 후 다른 날짜의 봉을 무조건 건너뛰지 않는다. 일반 청산 조건은 검사하고 시간 종료 조건만 목표 날짜로 제한한다. 다일 데이터 입력은 이 원본 동작을 그대로 따른다.

## 6. MFE 게이트의 실시간 의미
- 기준선 `capture × (1+α/100)`는 09:03 포착봉 종가로 정하므로 실시간으로 계산할 수 있다.
- `officialMfe` 사전 게이트는 "포착 종목이 당일 기준선 α 이상 올랐는가"를 뜻한다. 일반 진입은 이미 `close ≥ basePrice`를 요구하므로, 동일한 포착가·봉·MFE 산출 기준이라면 일반 진입과 사전 게이트의 관계를 비교할 수 있다. 공급자 정의까지 같다는 보장은 없으므로 별도 대사가 필요하다.
- 조기진입은 기준선 도달 전에 들어갈 수 있다. 그래서 실전에서는 백테스트에서 MFE미달로 제외된 종목에 진입하는 경우가 생길 수 있다. 이것이 조기진입을 선택 피처로 둔 이유다. 실전 호출은 `official_mfe=None`으로 사전 게이트를 사용하지 않고 `apply_mfe_gate=True`로 실시간 기준선을 유지한다. 기준선 미만 조기진입 여부는 이벤트 가격과 기준선을 비교해 저널에 기록할 수 있다. 일중 최종 MFE를 진입 시점에 사용하면 안 된다.

| 구성 | 환경 | 역할 |
|---|---|---|
| Trader Core | Python 64bit | 키움 REST/WS, 360틱 봉 생성, S4.3R 엔진(§5, 공용 모듈), 주문, 리스크, 저널 |

**엔진은 하나다.** 백테스트(감사파일 재생)와 실전(실시간 봉)이 같은 `evaluate` 함수를 봉 단위 상태기계로 호출한다. 실전용 엔진을 따로 만들지 않는다.

### 9.1 장중 흐름
1. 08:50 토큰 발급(au10001), 설정 확정
2. 09:03 조건식 92 조회(ka10171→ka10172) → 포착 전체 종목과 포착 수를 저장 → 조기진입 ON/OFF 결정
3. 종목별 360틱 시드(ka10079) → 지표 초기화 → capture, basePrice 확정
4. 실시간 체결(WS 0B) 360틱마다 봉 마감 → 엔진 step → 의도(진입/부분/청산) 발생
5. 주문관리기가 의도를 주문으로 바꾸고, 체결 수량으로 포지션을 갱신
6. 10:30 잔고 0 확인 → 장후 대사 및 일일 보고서

### 9.2 주문 규칙 (초안)
| 의도 | 방식 | 실패 처리 |
|---|---|---|
| 진입 | 지정가 = 신호 종가 + 2호가, 3초 | 미체결분 취소, 추격하지 않음 |
| 부분/전량 청산 | 최유리 | 5초 후 시장가 |
| 10:30 | 시장가 | 잔고 0까지 반복 |
- 부분익절 1·2차는 각각 **최초 체결 수량의 30%**다. `floor(현재 보유×0.3)`를 두 번 적용하면 30%+21%가 되어 전략과 다르다. 정수 수량 반올림과 잔량은 P2에서 확정한다. 0주면 생략하고 기록한다.
- 멱등키는 `날짜+종목+의도번호`. 같은 키로 두 번 주문하지 않는다.
- 비상 손절(엔진 외부): 틱 기준 −6%에서 즉시 청산하고 따로 집계한다. 엔진의 종가 손절 규칙은 바꾸지 않는다.

### 9.3 리스크와 복구
- 종목당 금액 X, 동시 보유 N, 일 손실 한도 −Y(도달 시 신규 진입 중단), 수동 킬스위치
- WS가 끊기면 재연결 후 ka10079로 빈 봉을 채우고 재계산한다. 3분 넘게 끊기면 신규 진입을 중단한다.
- 재시작하면 저널과 잔고조회, 봉 재생으로 엔진 상태를 복원한다.

### 9.4 실전 검증 지표 (매일 자동)
- 결정 일치율: 장후 같은 봉으로 백테스트를 재생해 실전 결정과 비교한다. 목표는 100%다.
- 봉 일치율: 실시간 생성 봉과 ka10079, Cybos 봉의 OHLCV를 비교한다.
- 슬리피지: 체결가와 신호 종가의 차이
- 당일 데이터는 감사파일 형식으로 data_validation에 저장한다. L3/L4 판정의 근거로 쓴다.

## 11. 원본 대조 결과
1. `static/app.js` 배치·차트 실행은 `input-macd-base`를 쉼표로 나누고 `parseFloat` 후 양수만 남겨 첫 값을 사용한다. 기본 `"0, 0.15"`는 0을 버려 0.15가 된다. 실제 브라우저 사용자 설정은 이 문서만으로 알 수 없다.
2. `s43_highestPrice`는 진입봉 고가로 초기화하고 다음 봉부터 손절 검사 **전에** 갱신한다. 이후 순서는 하드스탑 → BEP → 1차 → 2차 → ATR → ST/VWAP → 시간 종료다. 부분익절 2개와 잔량청산이 한 봉에 모두 일어날 수 있다.
3. 목표 날짜 조건은 진입 및 시간 종료에 적용한다. 다른 날짜 봉에서도 보유 관리가 실행된다. 미청산은 `미체결`, 손익 0이고, 미진입과 다르다.
4. `worker_bridge_32bit.py`는 전일 마지막 최대 80개 합성 틱봉을 시드로 사용한다. 실제 학습 파일에서는 0~80개다. Python 재생은 감사파일 배열을 정렬·절단·추가 보충 없이 그대로 사용한다.
5. 현재 360틱 수집기는 120틱 봉 3개를 합성하고 마지막 하위 봉의 HHMM을 쓴다. 일자별로 묶으며 남은 불완전 묶음도 출력한다. 실제 거래소 체결로 만든 360틱과 공급자의 120틱 묶음 경계·거래소 범위(KRX+NXT)가 일치하는지는 P1 과제다. 이는 로컬 코드에서 확인한 라벨링이며 외부 공급자의 시각 정의 검증을 대신하지 않는다.

## 12. P0 실행과 결과

```powershell
python -m unittest discover -s tests -p test_s43r_engine.py -v
```

Python 3.10+와 Node.js가 필요하다. 별도 Python 패키지는 필요 없다. `data/strategy-audit-YYYYMMDD-T-360.json` 20개는 로컬 자료이며 리포에 올리지 않는다. 파일이 없으면 Golden Set 테스트는 명시적으로 skip하고, 일부만 있으면 실패한다. `data_validation/` 및 9/30 이후 파일은 학습 테스트가 읽지 않는다.

| 조기 설정 | 청산 거래 | 비용 전 합계 | 비용 0.25%p 차감 합계 |
|---|---:|---:|---:|
| ON, 0.20 | 230 | +40.621765% | −16.878235% |
| ON, 0.30 | 200 | +77.645476% | +27.645476% |
| OFF, 0.20/0.30 | 119 | +66.676566% | +36.926566% |

손익은 거래별 수익률의 단순 합이며 포트폴리오 누적 수익률이 아니다. 이 표는 고정 학습자료 재현 결과이며 P1~P3 검증을 대신하지 않는다.

```python
from s43r_engine import StrategyConfig, S43REngine, evaluate

cfg = StrategyConfig(target_date="20260930", early_enabled=True, early_macd=0.30)
result = evaluate(candles, cfg)  # official_mfe=None: 사전 MFE 제외 없음
engine = S43REngine(cfg)
for closed_bar in candles:      # 같은 시드부터 순서대로, 미완성 봉을 반복 전달하지 않음
    intents = engine.step(closed_bar)
assert engine.result() == result
```

설정은 불변 dataclass다. 엔진은 하나의 종목·하나의 목표 날짜 단위로 생성한다. 종목 간 상태를 공유하지 않는다. 이벤트는 주문이 아니며 실제 체결 수량·미체결·복구 상태와의 연동은 P2 범위다. 재시작 시 동일 봉을 처음부터 재생하여 상태를 복원할 수 있지만 저널/잔고 대사는 아직 구현하지 않았다.
